# RPG游戏地图AI生图辅助编辑器

一个面向 **2D RPG 地图创作** 的 Codex skill，附带可离线运行的 **RPG游戏地图编辑器**。编辑器帮助你把地图尺寸、边界、可走区、物件占地、通路开口和参考图变成明确的生图底座；skill 则指导 AI 按几何和样式约束生成候选图，并在需要时接入 Godot。

适用场景包括室内房间、街道、庭院、树林、走廊及其他 2D 地图。工具本身不含任何游戏项目的数据或素材。默认只是一个空白地图配置，使用者应依据自己的地图修改数值。

## 能做什么

- 在浏览器里绘制地面轮廓、可走区、物件占地和通路开口，支持拖动节点、移动或缩放矩形、撤销。
- 为轴对齐的正交斜俯视室内地图，按自填尺寸生成上墙面、左右墙顶、下墙顶及墙角连接。墙体功能可完全跳过。
- 叠加当前地图参考图，并加入多张相邻地图或角色比例参考层；参考层可拖动、调整尺寸和透明度。
- 导出可继续编辑的 JSON、只含几何标记的 PNG 生图底座，以及供人工检查拼接关系的视图 PNG。
- 用 skill 的步骤检查 AI 生成图是否遵守边界、视角、落地点和指定样式；如需可玩地图，再按目标项目架构制作碰撞、遮挡、出生点与交互。

编辑器是**规划和约束工具**。它不会调用图像模型，也不会自动生成 Godot 场景、碰撞或导航。AI 绘制的候选图仍需人工核对；只有完成引擎接入和运行验证后，才能称为可玩地图。

## 开始使用

### 直接使用编辑器

1. 下载仓库，双击打开 [`assets/rpg-map-editor.html`](assets/rpg-map-editor.html)。它是单文件 HTML，无需安装服务或依赖；使用现代桌面浏览器即可。
2. 在“实际生图区域”设置地图 ID、源图宽高、Godot 世界缩放和网格，点击“应用并适配视图”。
3. 按场景需要选择“地面轮廓”“可走区域”“物件占地”“通路开口”；多边形逐点单击，点击“闭合当前多边形”结束；矩形用鼠标拖出。
4. 如需参考，把图片加入“当前地图参考图”或“比例与拼接参考层”。可为参考图注明用途和允许/禁止继承的特征。
5. 导出 JSON 保存编辑进度，导出 PNG 生图底座供后续图像生成使用。重新打开编辑器时可以导入 JSON。

鼠标滚轮缩放；鼠标中键、右键或“平移视图”拖动视野。参考层遮住绘制区域时，按住 `Alt` 再绘制。每个带 `!` 的控件都有功能说明。

### 作为 Codex skill 使用

把整个仓库目录复制到 Codex 的 skills 目录，并保持 `SKILL.md`、`assets/`、`references/` 的相对位置。例如：

```text
~/.codex/skills/rpg-map-ai-design-skill/
```

安装后可在请求中写：

```text
使用 $rpg-map-ai-design-skill，为一张 2D RPG 街道地图规划生图底座。
画布 1920×1080，先确定道路、可走区和两个出口，再参考我提供的图生成底图候选。
```

如果只需要编辑器，可直接打开 HTML；不必安装 skill。

## 空白配置

| 项目 | 初始值 | 说明 |
| --- | ---: | --- |
| 地图 ID | `map` | 用于导出文件名 |
| 源图尺寸 | `1920 × 1080` 像素 | 可自由修改 |
| Godot 世界缩放 | `1` | 仅写入 JSON；不会改变 PNG 像素尺寸 |
| 网格 | `16` 像素 | 绘制吸附间距 |
| 场景视角 | 未指定 | 按地图选择俯视、斜俯视、等距或其他 |
| 五项墙体尺寸 | 均为 `0` | 不会默认生成墙体 |
| 比例参考层名称 | 空 | 添加时可自行命名 |
| 比例参考层尺寸 | `1920 × 1080` 像素 | 加载图片后自动读取其原始宽高，也可改动 |
| 比例参考层位置 | `X = 0, Y = 0` | 相对生图区域左上角 |
| 参考图与比例参考层透明度 | `50%` | 只影响编辑视图 |

这些数字只是编辑器启动值，并不代表推荐地图规格。创建室内地图时按实际墙体设置尺寸；街道、森林等场景可以保持墙体为 0。

## 三种导出文件

| 导出 | 用途 | 参考图片是否包含在可见像素中 |
| --- | --- | --- |
| `<map-id>-map-base.json` | 继续编辑地图底座；保存几何与参考图 | 参考图以 data URL **内嵌在文件中** |
| `<map-id>-map-base.png` | 交给图像生成工具的边界与布局提示 | 不含参考图、角色比例图和编辑参考线 |
| `<map-id>-reference-layout.png` | 人工核对比例、拼接位置和视图 | 含当前可见参考层 |

JSON 中的主要字段为 `map_id`、`canvas`、`world_scale`、`grid_size`、`map_outline`、`walkable`、`objects`、`doors`、`wall_profile`、`wall_surfaces`、`wall_corners`、`reference` 和 `scale_references`。其中 `objects` 的矩形表示地面占地；物件完整绘制高度需要另行确定。`doors` 是通路开口的规划标记，不会自动修改引擎碰撞。

**公开分享 JSON 前请检查内嵌图片。** 参考图可能受版权保护，也可能包含私人内容；图片越多，JSON 文件越大。此仓库本身不包含任何用户地图、参考图或导出 JSON。

## 推荐生图流程

1. 确定视角、画布尺寸、地图外形、玩家可走区域与出口。先画底座，再生图。
2. 为每张参考图明确用途：几何、整体样式、指定物件或错误反例。指定样式时写清楚必须保留的造型、材质、配色、纹理和结构。
3. 将生图底座 PNG 与有权使用的参考图交给图像生成工具；说明哪些边界、通路、物件占地不能变化。
4. 把候选图与底座叠加检查。几何或指定样式偏离时重生；不要用拉伸去掩盖结构错误。
5. 高分辨率地图先做完整母图，再局部重绘并检查接缝。需要玩家从前后绕行的前景物件，应另做透明遮挡层。
6. 若目标是可玩场景，按项目已有结构接入碰撞、出生、出口和交互，最后在引擎内实际走动验证。

提示词可从这个结构开始，按实际地图补全：

```text
生成一张 2D RPG 地图底图。严格保持底座 PNG 的画布比例、地面边界、可走通路、开口和已标出的物件占地。
视角：[明确俯视/斜俯视/等距等视角与一致的投影规则]。
指定样式：[逐项列出参考图对应区域与必须保留的特征]。
可自由设计：[明确允许 AI 自行设计的区域或物件]。
禁止：[移动边界、堵塞通路、混合视角、漂浮物件、添加文字等]。
需要动态遮挡的物件另做透明层，不在背景中烘焙。
```

## 与 Godot 的关系

编辑器记录源图像素坐标与 `world_scale`，供后续统一换算。真正接入时，要结合项目的 `Sprite2D` 原点、玩家脚点、碰撞尺寸和场景切换方式。地图图片本身不等于可玩场景。具体接入检查见 [`references/godot-integration.md`](references/godot-integration.md)。

本 skill 以 Godot 4.x 接入为参考，但几何底座和 AI 生图流程也可用于其他 2D 引擎。四向墙体生成器只对应轴对齐的正交斜俯视室内边界；其他投影或开放场景请使用基础几何工具，不使用该墙体生成器。
